# #226 내 연습 기록

Status: DONE
Date: 2026-10-04
Issue: https://github.com/landfill/ClairKeys/issues/226

## Objective and chosen scope

사용자가 2026-10-04 "1. 권장안"을 선택했다. 로그인 사용자의 기존 곡별 연습 기록(횟수·시간·최근 연습일·최고 재생 도달률)을 모아 보여준다.
비로그인 저장, 레슨 열람/완료 판정, 정적 코스의 계정 기록은 추가하지 않는다. 기존 PracticeSession 재사용, DB schema/migration 없음(D-098).

## Work stages

1. `/api/practice` GET의 인증·사용자별 분리·현재 악보 접근권한·페이지 조회 회귀 테스트.
2. 읽을 수 있는 악보의 현재 사용자 기록만 곡별 집계. 최초 조회에서 보이는 최대 기록 ID 이하를 최근 연습순 20곡씩 cursor 조회, private/no-store 응답.
3. `/practice` 로그인 전용 화면: 곡별 횟수·총 재생 시간·최고 재생 위치·최근 연습일·곡으로 이동.
4. 배우기 홈에서 진입. `/learn` 공개성 유지, 재생 루트·헤더 메뉴는 변경하지 않는다.
5. 로딩·빈 상태·실패/재시도·페이지 이동·비로그인 접근 E2E 및 320px 화면 확인.

## Constraints

세션 userId를 기준으로 조회하며 요청의 사용자 ID를 받지 않는다. 공개를 해제한 타인의 악보는 기록에서도 숨긴다.
최고 %는 도달한 재생 위치이며 정확도·숙련도·레슨 완료 판정으로 표시하지 않는다. 계정 전환/이탈 시 이전 요청을 취소하고 이전 기록을 남기지 않는다.
10초 미만을 기록하지 않는 기존 쓰기 규칙은 변경하지 않는다. 운영 DB 변경/배포 없음.

## Completion criteria

위 기능과 인증·접근 경계 검증, 전체 로컬 테스트·CI·리뷰, 사용자 승인 후 병합·Post-merge·이슈 상태 일치.
명령·결과·한계의 원본은 [구현 검증 기록](../validation/2026-10-04-issue-226-practice-history.md)이다.

### 초기 PR235 P2 대응 (아래 DB 기준점 방식으로 대체)

offset은 페이지 사이에 기록이 추가되거나 공개 상태가 달라지면 중복/누락을 만든다. 서버의 조회 시작 시각(asOf)으로 기록 집합을 고정하고,
마지막 집계 날짜와 곡 ID보다 뒤에 있는 그룹을 keyset으로 조회한다. 이전 페이지도 같은 기준 시각의 cursor를 보관해 돌아간다.
현재 접근권한은 매 요청에 계속 검사한다. 새 연습 기록은 화면을 다시 열 때 새 조회에 반영된다.

### DB 기준점 리뷰 대응

앱 시계 asOf를 제거하고 최초 조회에서 DB에 보이는 최대 PracticeSession ID를 cursor에 고정한다. 모든 페이지의 집계에 `id <= maxSessionId`를 적용한다.
현재 사용자의 접근 가능한 기록에서 기준 ID를 얻고 다음/이전 페이지에서는 다시 계산하지 않는다. DB 시계가 앱보다 앞서거나 이후 입력이 과거 createdAt을 갖더라도
새로 할당된 ID는 기존 조회에 들어오지 않는다. timestamp는 곡별 정렬과 keyset 위치에만 쓴다.
