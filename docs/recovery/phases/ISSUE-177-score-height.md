# ISSUE-177 — PC 악보와 건반의 세로 공간 배분

Status: `DONE` — PR #183 merged `4803bba` on 2026-09-22; all post-merge checks passed.
Issue: https://github.com/landfill/ClairKeys/issues/177
Base: 2026-09-22 main; 기존 재생·OMR 계약 유지.

## Objective

PC 재생 중 양손 악보 한 줄의 음표·운지·슬러·보표 밖 기호가 패널의 고정
`clamp(240px, 34vh, 360px)` 높이 때문에 잘리는 문제를, 사용 가능한 세로 공간에
맞춰 완화한다. 건반 가로 geometry, 노트 시간·오디오, 기존 모바일 재생 동작은 보존한다.

## Current live evidence and changed sample IDs

2026-09-22 운영 `/sheet/87`, `/88`, `/89`는 모두 "악보를 찾을 수 없습니다".
동일 제목의 새 `/sheet/90` Love Affair, `/sheet/91` Deborah's Theme,
`/sheet/92` Clair de Lune가 존재한다. 같은 제목만으로 악보/OMR 바이트 동일성을
추정하지 않는다. 2026-09-21 [기존 실측](../validation/2026-09-21-score-panel-height.md)은
역사적 기준선으로 보존하고, 새 ID는 별도 현재 기준선으로 측정한다.

운영 재생/일시정지 실측: 1280×720의 #90 악보 표시243px 대 양손 줄 최대368.6px
(7줄 중 모두 초과), #92 표시243px 대 최대311.9px(3줄 중 모두 초과).
1440×900의 #91은 표시289px 대 최대270.5px(6줄 모두 이내)이며 현재 충분한
조건의 보존 사례다. #90 약20초와 #92 약25초에서 잘린 보표·기호를 확인했다.

## Work stages

1. 실제 score content height, 가로 overflow, 남는 세로 여백, 건반·낙하 영역의
   변경 전 치수를 수집한다. 동작 변경 전 예산 계획과 브라우저 회귀를 추가해 실패를
   재현한다.
2. 악보의 현재 마디가 아닌 **전체 양손 시스템** 최대 높이를 렌더링 후 측정한다.
   세로 공간 예산은 viewport/재생 UI에서 안정적으로 계산하고, 이미 충분한
   조건은 그대로 둔다.
3. 빈 여백을 먼저 악보에 배정하고 부족할 때 PC 악보 ON의 건반 세로만 안전한
   하한까지 줄인다. 낙하 영역 높이와 px/s·lookahead는 기준선보다 줄이지 않는다.
   너무 높은 시스템은 패널 상한 안에서 스크롤할 수 있게 두고, 자동 스크롤은
   시스템 윗부분의 운지·슬러를 가리지 않도록 한다. 전체 배율을 무조건 줄이지 않는다.
4. 90·91·92와 높은/낮은 음역·운지·긴 슬러 fixture를 여러 PC viewport에서
   검증한다. 이슈의 87·88·89는 현 운영 404를 한계로 기록한다. 악보 OFF/모바일,
   MusicXML 없는 곡, 앞뒤 탐색·일시정지·줄 전환·창 변경을 회귀 검증한다.

## Completion criteria

- 같은 viewport에서 모든 건반의 x/폭/간격/음역 순서는 변경 전과 같다. 키 전체
  `scale()`/`scaleY()` 금지. 흰/검은 건반의 길이만 조절하고 운지·음이름 글자 크기와
  겹침 방지를 검증한다.
- 악보 확장 전후 낙하 영역의 픽셀 높이와 미리 보이는 시간, 기본140px/s,
  히트라인, 노트 길이, 오디오 동기화가 줄거나 어긋나지 않는다.
- 시스템 전체가 예산 안에 들면 양손 보표·운지·슬러가 동시에 보이고, 예산 초과
  예외는 원인·상한·스크롤 위치·가독성 한계를 명확히 기록한다. 패널이 마디마다
  출렁이거나 ResizeObserver 피드백 루프를 만들지 않는다.
- 1366×768, 1440×900, 1920×1080과 PC 확대/가로 스크롤바, 모바일, 악보 OFF를
  구분해 실제 화면·치수로 검증한다. 모든 곡/화면의 한 화면 완전 표시를 단정하지 않는다.
- 회귀 근거, 타입·lint·build·관련 Jest/Playwright, non-draft PR, 현재 head CI·리뷰
  대응을 recovery에 남긴다. PR 병합은 별도 사용자 명시적 승인 전 하지 않는다.

## Scope boundary

새 `follow`/`practice` 기능, OMR·DB·데이터 계약·공개 권한 변경은 이 단계에 없다.
