# FEAT — 기다리기 모드와 MIDI 입력

Status: `IN_PROGRESS` — branch `codex/feat-wait-mode-midi`.
Base: 2026-09-27 main `2c30399`. 사용자가 2026-09-27 추천안(MIDI와 화면 건반 둘 다, 사용자가 낸 소리만)을 승인했다.

## Objective

"악보를 몰라도 따라 친다"는 목표에 맞게, 맞는 건반을 누를 때까지 곡이 멈춰서 기다리는 연습 방식을 추가한다.
D-079가 요구사항 미정으로 보류했던 `follow` 성격의 기능을 새 계약(D-086)으로 구현한다. 레거시
`AnimationPlayer`의 practice 엔진은 쓰지 않는다.

## Contract (D-086)

- 입력: Web MIDI note-on(모든 입력 장치, 연결 후 추가된 장치 포함)과 화면 건반 pointerdown. MIDI 권한은 기다리기
  모드를 켜는 클릭에서만 요청한다. Safari·iOS처럼 Web MIDI가 없거나 거부되면 화면 건반을 안내한다.
- 단계: 시작 시각이 30ms 안인 노트는 한 단계다. 같은 음은 한 번만 누르면 된다. 순서는 상관없고 틀린 건반은 무시한다.
- 시계: 기다리기 모드의 재생은 소리 없이 시계만 흐르고, 다음 단계 시각에 정확히 멈춘다. 단계를 모두 누르면 그
  단계 시각부터 다시 흐른다. 일시정지·속도 변경은 대기를 끝내되 단계는 미완료로 남아 다시 만나면 기다린다.
  재생 위치 이동은 그 위치의 단계부터 기다린다.
- 소리: 사용자가 낸 소리만 난다. MIDI 피아노는 스스로 소리를 내고, 화면 건반은 `playNoteNow`로 즉시 발음하며
  이 소리는 예약 재시작에 끊기지 않는다.
- 화면: 대기 중 건반에는 남은 음만 강조하고 낙하 영역 위에 `건반을 눌러 주세요 · 남은 음 n개`를 표시한다.

## Completion criteria

- 단계 구성·MIDI 파싱·MIDI 훅·화면 건반 입력·즉시 발음·재생 훅 대기·플레이어 UI 테스트가 구현 전에 실패한다.
- 실제 브라우저에서 가짜 MIDI 입력과 화면 건반으로 단계가 진행되고, 대기 중 시계가 멈춰 있다.
- 관련 unit/E2E·타입·lint·build 통과, non-draft PR과 CI·리뷰 처리. 사용자 승인 전 병합하지 않는다.

## Out of scope

한 손 연습(PR191)과의 결합(병합 후 `isPracticedNote`로 단계를 좁히는 후속), 정확도 점수·틀린 건반 표시,
벨로시티·페달, 재생 중(압축 바) 토글, 컴퓨터 키보드를 건반으로 쓰는 입력.
