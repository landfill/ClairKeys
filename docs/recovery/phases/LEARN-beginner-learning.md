# LEARN: 초보자 학습 영역 (`배우기`)

Status: PLANNED
Date: 2026-10-03
Issue: [#208](https://github.com/landfill/ClairKeys/issues/208)
Decision: [D-094](../DECISIONS.md)

## Objective

악보를 거의 읽지 못하는 완전 초보자(#76의 대상)가 건반·악보·손가락 번호를 이해하도록 돕는 학습 콘텐츠를 만든다.
콘텐츠는 새 `배우기` 영역의 페이지로 두고, 재생 화면에는 치는 동안 필요한 최소 표시만 더한다.
사용자가 가져온 곡과 레슨은 곡 소개로 연결한다.

## 현재 상태 (2026-10-03, `main` `d896b85`)

- 메뉴: `Header`의 `내 악보`·`새 악보`(로그인 시)와 `탐색`. 학습 페이지 없음.
- 재생 화면 `src/components/animation/FallingNotesPlayer.tsx`(910줄): 재생·위치·A-B 반복·빠르기·양손/한 손·메트로놈·
  기다리기(MIDI)·악보 패널·이어서 연습·"연습 방법" 3줄 목록(597행)·키보드 단축키 안내(752행).
- 초보자용 설명은 위 3줄 목록과 단축키 안내뿐이다. 계이름·가운데 도 표시 없음.
- `src/components/animation/AnimationPlayer.tsx`의 `PracticeGuideControls`("연습 가이드 모드")는 `LazyComponent`에서만
  참조된다. 실제 화면에서 쓰이는지 L-3에서 확인하고, 쓰이지 않으면 범위 밖 정리 후보로 기록한다.
- 재사용 자산: `src/utils/pianoLayout.ts`(88건반 배치, `isBlack`), `src/utils/pianoSampleBank.ts`(피아노 샘플),
  재생 엔진(`useFallingNotesPlayer`), 악보 패널(`ScorePanel`), 운지 데이터, 애니메이션 계약의 `timeSignature`·`keySignature`.
- 접근: `src/middleware.ts`는 `isProtectedPath`(`src/lib/routeAccess`)에 든 경로만 로그인 요구. `/learn`은 넣지 않는다.

## 화면 배치 원칙 (D-094)

| 위치 | 둘 것 | 두지 않을 것 |
|---|---|---|
| 재생 화면 | 치는 동안 보는 표시(계이름 토글, 가운데 도 표시), 해당 레슨으로 가는 도움말 링크 | 여러 줄 설명, 레슨 본문, 연습 요령 목록 |
| `배우기` 페이지 | 치기 전·후에 읽고 익히는 내용, 인터랙티브 예시 | 실제 곡 재생기 전체 |
| 곡 소개 | 그 곡에 필요한 개념 요약과 레슨 링크 | 레슨 본문 복제 |

재생 화면의 보이는 요소 수는 늘지 않아야 한다(L-3에서 옮긴 설명 ≥ 새로 더한 요소).

## Work stages

각 단계는 별도 브랜치(`codex/learn-<n>-<topic>`)와 PR이다. 순서는 L-1 → (L-2, L-3) → L-4 → L-5 → L-6.
L-2와 L-3은 서로 다른 파일을 소유하므로 L-1 병합 후 어느 쪽을 먼저 해도 된다.

### L-1 `배우기` 골격

- `Header`(데스크톱·모바일)에 `배우기` 메뉴 추가. 비로그인에도 보인다. 순서: `배우기`·`탐색`·`내 악보`·`새 악보`.
- `/learn` 홈: 단계 지도(건반 → 악보 읽기 → 손 → 연습 방법), 각 카드에서 레슨으로 이동. 아직 없는 레슨은 링크하지 않는다.
- 공통 레슨 레이아웃(제목, 이전·다음 레슨, 단계 지도로 돌아가기). DS-1 토큰만 사용, 새 토큰 추가 금지.
- 완료: 비로그인 `/learn` 200, 메뉴 노출·키보드 탐색 E2E, 접근성(제목 구조, 링크 이름).

### L-2 건반 익히기 `/learn/keyboard`

- 인터랙티브 건반: 누르면(마우스·터치·키보드·MIDI 있으면 MIDI) 계이름과 소리. `pianoLayout`·`PianoSampleBank` 재사용.
- 가운데 도(C4, MIDI 60) 표시, 검은 건반 2개·3개 묶음으로 도 위치 찾는 법.
- "도 찾기" 연습: 무작위 옥타브의 도를 누르게 하고 맞음/다시를 표시.
- 완료: 계이름 매핑 단위 테스트(88건반 전체), 연습 판정 단위 테스트, chromium E2E(누르기·판정), 소리 없이도 동작(음소거·샘플 실패).

### L-3 재생 화면 정리와 계이름 토글, `/learn/practice`

- 재생 화면의 "연습 방법" 3줄 목록과 키보드 단축키 안내를 `/learn/practice`로 옮기고, 재생 화면에는 도움말 링크 하나를 둔다.
- 계이름 표시 토글(기본 꺼짐): 건반 위 계이름, 가운데 도 강조. 설정은 브라우저에 기억(실패해도 동작).
- `/learn/practice`: 느리게 시작, 한 손씩, A-B 구간 반복, 기다리기 모드, 메트로놈, 단축키.
- 완료: 재생 화면 요소 수 비교 기록, 토글 단위·E2E, 기존 재생 E2E 회귀 없음, 회전 화면에서 레인을 가리지 않음.

### L-4 악보 읽기 `/learn/reading`

- 오선과 높은음자리표·낮은음자리표, 오선 위치 ↔ 건반 ↔ 계이름, 음표·쉼표 길이(온·2분·4분·8분, 점음표), 박자표(4/4·3/4·6/8).
- 각 예시는 짧게 들어 볼 수 있다(기존 샘플·재생 엔진 재사용). 악보 그림은 정적 SVG 또는 기존 악보 렌더링 중 단계 시작 시 선택해 기록.
- 내용이 많으면 음높이(L-4a)와 길이·박자(L-4b) 두 PR로 나눈다.
- 완료: 예시 데이터 단위 테스트(음높이·길이), E2E, 이론 대조 근거(아래 "내용 정확성").

### L-5 손 자세와 손가락 번호 `/learn/hands`

- 손가락 번호 1~5(양손), 기본 손 모양, 다섯 손가락 자리(도~솔).
- 재생 화면의 운지 표시에서 이 레슨으로 가는 링크(재생 화면 요소 수 원칙 유지).
- 완료: E2E, 이론 대조 근거.

### L-6 곡 소개

- 곡 데이터에서 박자·조·나오는 음표·쉼표 종류·음역(가장 낮은/높은 음)·양손 여부·길이를 뽑아 보여 주고, 각 항목을 해당 레슨으로 연결한다.
- 진입 위치(재생 전 별도 경로 또는 `/sheet/[id]` 안의 소개 단계)는 단계 시작 시 결정해 DECISIONS에 기록한다.
- 진입 조건: 애니메이션 JSON에서 음표 길이 종류를 신뢰성 있게 복원할 수 있는지 먼저 확인한다. 불가능하면 그 항목은 빼고 나머지로 진행한다.
  D-049/D-052에 따라 데이터에 없는 정보를 추정해 채우지 않는다.
- 완료: 분석 단위 테스트(대표 fixture), 비공개 악보 접근 규칙 유지, E2E.

## 내용 정확성

사용자는 악보를 읽지 않고 청취로 오류를 구분하기 어렵다. 이론 설명은 청취가 아니라 다음으로 확인한다.

- 계이름·음높이 매핑은 MIDI 번호 기준 단위 테스트로 고정한다.
- 용어와 설명은 표준 교재 정의와 대조한 표를 각 단계 validation에 남긴다(출처 명시).
- 표기: 건반 위 계이름은 C=도 고정(`도 레 미 파 솔 라 시`), 가운데 도는 C4(MIDI 60). 다른 표기 도입은 별도 결정.

## 작업 방식 (오케스트레이션)

사용자 지시(2026-10-03): 구현은 Codex `gpt-6.1-sol`, 리뷰는 Codex `gpt-6-astra` reasoning `high`.
Claude는 오케스트레이션만 한다(직접 구현하지 않는다).

| 역할 | 담당 | 하는 일 |
|---|---|---|
| 오케스트레이션 | Claude | 단계 착수(브랜치), 구현 지시문 작성, 결과 확인, 리뷰 지적 분류, PR 생성·CI 확인, 상태 기록(main), 사용자 승인 요청 |
| 구현 | `codex exec -m gpt-6.1-sol` | AGENTS.md 규약대로 재현 테스트 → 구현 → 로컬 검증 → validation 기록 → Lore 커밋(작업 브랜치) |
| 리뷰 | `codex review --base main -c model="gpt-6-astra" -c model_reasoning_effort="high"` | 작업 브랜치 diff 리뷰. 지적은 `reviews/PR-<n>.md`에 기록하고 유효한 것은 구현 모델이 수정 |

- 구현 모델의 reasoning effort는 지정되지 않았다. `~/.codex/config.toml` 기본값(`ultra`)을 따른다. 바꾸려면 사용자 지시로 이 표를 갱신한다.
- 리뷰는 PR 생성 전 로컬 1회, 수정 커밋 뒤 재리뷰. GitHub의 Codex 봇 리뷰도 기존대로 처리한다.
- 구현 결과는 오케스트레이터가 명령·결과 기록과 diff로 확인한다. 같은 트리의 전체 검증을 다시 돌리지 않는다(D-088).
  기록과 실제가 다르거나 기록이 없으면 그 검증만 다시 돌려 확인한다.
- 병합은 PR마다 사용자의 명시적 승인 후에만 한다.

## Completion criteria

- 비로그인 처음 방문자가 메뉴 `배우기`에서 건반 → 악보 읽기 → 손 → 연습 방법을 순서대로 볼 수 있다.
- 재생 화면의 보이는 요소 수가 L-1 이전보다 늘지 않는다.
- 내 곡의 소개에서 그 곡에 필요한 레슨으로 이동할 수 있다.
- 각 단계의 이론 대조 근거와 검증 기록이 `validation/`에 있다.
- 선택: 초보자 3~5명 관찰 테스트(DS-2와 같은 방식). 실행하면 결과를 기록한다.
