# DS-7 — 알림·빈 화면·오류 상태 완결

Status: `NOT_STARTED`
Depends on: **DS-2, DS-3, DS-4, DS-5, DS-6 전부**
Issue: [#76](https://github.com/landfill/ClairKeys/issues/76) 7단계

## Objective

각 단계가 만든 화면들의 빈 상태·오류 상태·복구 행동을 하나의 규칙으로 통일하고, 홈에서 첫 재생까지의
여정을 종단 검증한다. 이슈 #76을 닫을 수 있는지 판정하는 단계다.

## 왜 마지막인가

이 단계의 범위가 "**각** 핵심 화면의 빈 상태·오류 상태·복구 행동 통일"이다. 통일 대상 화면이 모두
확정되기 전에는 끝낼 수 없다. DS-3·DS-4만 선행 조건으로 두면 DS-2(홈·로그인)·DS-5(플레이어)·
DS-6(탐색·상세)의 화면이 나중에 들어오면서 통일이 다시 깨진다.

## In scope

- 변환 완료 알림과 전역 상태 진입점 (**DS-G1의 결정을 따른다**)
- DS-2~DS-6이 확정한 모든 화면의 빈 상태·오류 상태·복구 행동 통일
- 오류 문구의 톤과 구조 통일 (무엇이 잘못됐는지 / 무엇을 하면 되는지)
- 종단 검증: 홈 → 업로드 → 페이지 이탈 → 완료 → 첫 재생

## Out of scope

- 각 화면의 주 레이아웃 (해당 단계 소유)
- 새 기능 추가
- DS0-1 (비공개 악보 public 버킷 노출) — DS 범위 밖

## 대상 화면과 소유 경계

| 화면 | 이 단계가 하는 것 | 하지 않는 것 |
|---|---|---|
| 홈 (DS-2) | 샘플 로딩 실패 상태 | 히어로·CTA 구성 |
| 로그인 (DS-2) | 인증 오류 문구 통일 | 이유 3가지·복귀 계약 |
| 업로드 (DS-3) | 오류 문구·복구 행동 통일 | 드롭존·상태 분리 |
| 내 악보 (DS-4) | 빈 상태 문구 통일 | 목록·상태 배지 구조 |
| 플레이어 (DS-5) | 데이터 로딩 실패 상태 | 컨트롤·기하 |
| 탐색·상세 (DS-6) | 결과 없음·접근 불가 상태 | 카드·퍼널 |

## 회귀 기준

**기능 회귀** — 앞 단계들이 고정한 모든 계약이 그대로다.

- 재생 기하 상수 7개와 D-019 가로 전환 조건식 (DS-5)
- `playback-chrome` (DS-1)
- 로그인 후 복귀 (DS-2), 비공개 악보 403 (DS-6)
- canonical 업로드 경로와 callback 저장 (DS-3)
- DS-G1이 정한 상태 출처 (DS-3, DS-4)

**시각 회귀** — DS-1 토큰만 사용한다.

## 접근성·반응형 검증

- 모든 오류·빈 상태가 색상 외 수단을 동반한다.
- 상태 전환이 `aria-live`로 전달되고, 포커스가 사라지지 않는다.
- 전역 알림 진입점이 키보드로 도달 가능하다.
- **WCAG AA 종단 판정** — 자동 검사(axe 등)를 전 화면에 실행하고 결과를 기록한다. DS-0 시점에
  한 번도 실행된 적이 없다.

## Completion criteria

- 각 화면의 빈 상태와 오류 상태가 같은 구조(무엇이 잘못됐는지 + 무엇을 하면 되는지)를 따른다.
- 완료 알림이 DS-G1의 결정대로 동작하거나, 알림을 두지 않기로 한 경우 그 결정이 문서에 있다.
- **종단 시나리오가 설명 없이 완주된다**: 로그아웃 상태 홈 진입 → 샘플 체험 → CTA → 로그인 →
  업로드 → 페이지 이탈 → 완료 확인 → 첫 재생. 수동 실행 기록을 남긴다.
- WCAG AA 자동 검사 결과가 기록되어 있고, 남은 위반이 있으면 각각에 판단(수정/유예)과 이유가 있다.
- **이슈 #76 전체 완료 조건 8개**(ROADMAP)에 대한 판정이 기록되어 있다.
- DS-0의 "변경하지 않을 회귀 계약"이 종료 시점에도 그대로임을 확인했다.
