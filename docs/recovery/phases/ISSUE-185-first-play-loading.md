# #185 첫 재생 샘플 로딩

Status: IN_REVIEW
Date: 2026-09-28
Issue: https://github.com/landfill/ClairKeys/issues/185

## Objective

첫 재생에서 녹음 피아노 샘플을 기다리는 동안 재생 화면이 0:00에 멈춘 것처럼 보이지 않게 한다. 기다리는 시간 자체도 줄인다.

## 재현 (2026-09-28, 운영 `/sheet/92`, 새 브라우저 컨텍스트·서비스 워커 차단, PC 1440×900)

| 회선 | 클릭 → 재생 위치가 0:00을 벗어남 | 샘플 |
|---|---|---|
| 제한 없음 | 1.6초 | 0.5초에 30/30, 녹음 피아노 |
| 4G급(1.6Mbps, 150ms) | 3.9초 | 2.5초 대기 한도 초과, 10/30 → 합성음 |
| 느린 4G(0.6Mbps, 400ms) | 3.9초 | 0/30 → 합성음 |

- 클릭 전 샘플 요청 0건: `getPianoSampleBank`가 첫 재생의 `initializeAudio`에서야 불린다.
- 재생 세션이 시작되면 샘플 상태 문구가 `sr-only`가 되어 화면에 로딩 표시가 없다.
- 서비스 워커가 있으면 샘플은 그 캐시에서 온다(재방문은 빠르다). 문제는 첫 방문이다.
- 측정 스크립트는 validation 기록에 둔다.

## Work stages

1. 재현 테스트: 페이지 진입 후 클릭 전 샘플 요청, 재생 세션의 로딩 표시, 합성음 대체 안내(Jest·Playwright). 수정 전 실패 확인.
2. 미리 받기: 악보 플레이어가 마운트되고 브라우저가 한가할 때 샘플 바이트를 받아 두고, 샘플 뱅크가 재생 때 그 바이트를
   디코딩한다(같은 요청을 두 번 하지 않는다). Save-Data 사용자는 미리 받지 않는다. 대기 한도·실패 시 합성음 동작은 그대로다.
3. 대기 표시: 세션은 오디오가 시작된 뒤에만 열리므로(D-056) 첫 재생의 대기는 설정 화면에서 일어난다(2026-09-28 운영 캡처로
   확인, 이슈의 "즉시 재생 모드"는 대기 뒤 첫 1초의 0:00 표시와 합쳐진 관찰). 누른 재생 버튼을 "준비 중"으로 바꾸고
   노트 영역 위에 오버레이를 띄운다(200ms 넘는 대기만). 스크린리더 알림은 기존 status 영역이 맡는다.
   합성음 대체(`degraded`/`failed`)는 재생 화면에 4초간 보인다(D-089).
4. 검증: 관련 Jest·전체 Jest·tsc·lint, 변경 영역 Playwright, preview에서 변경 전후 첫 재생 시간 측정.

## Completion criteria

- 샘플을 기다리는 동안 PC·모바일 재생 화면에 로딩 표시가 보이고, 끝나면 사라진다. 스크린리더 알림은 유지된다.
- 합성음 대체 안내가 재생 화면에서도 보인다.
- 첫 방문에서 페이지를 보는 동안 샘플을 미리 받아, 같은 회선에서 첫 재생까지의 시간이 줄어든다(변경 전후 측정 기록).
- 실패·지연 시 동작(2.5초 한도, 합성음 대체)은 바뀌지 않는다.
