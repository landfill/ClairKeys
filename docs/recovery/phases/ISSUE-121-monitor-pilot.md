# ISSUE-121: 서비스 내부 OMR 관측 파일럿

## Status

IN_PROGRESS — 2026-11-03 사용자 구현·PR 요청. #121의 보류는 이 파일럿에 한해 해제.

## Objective

기존 서비스 `/admin/omr`에서 운영자가 실제 OMR 연결·실행·작업·전달·자원을 읽기 전용으로 확인한다.
별도 서비스·로그인·DB·영속 큐 없이 D-104의 제한된 계측을 도입한다.

## Entry conditions

- 사용자 요청으로 구현·검증·push·review-ready PR·CI/리뷰 대응 승인.
- 병합과 운영 배포·재시작·설정 변경은 각각 별도 승인 필요.

## Work stages

1. 실패하는 권한·스냅샷·실패 격리 회귀를 먼저 작성한다.
2. OMR 단계 계측과 인증된 스냅샷, 최소 권한 호스트 수집기를 구현한다.
3. 서버 권한 검사·응답 allowlist·운영자 메뉴·모바일 화면과 갱신을 구현한다.
4. Python·Jest·타입·lint·Playwright·브라우저 확인 후 PR과 CI·리뷰를 처리한다.

## Completion criteria

- 페이지와 API를 직접 요청해도 비운영자는 데이터를 받지 못한다.
- 실제 계측은 민감정보를 제외하고 시각·단위·범위·초기화를 명시한다.
- 최근 완료 작업은 최대 100건·1시간, 실행 중 작업은 종료까지 관측한다.
- 큐 대기는 실제 Audiveris slot 대기와 구분하고 callback 실패는 변환 성공을 바꾸지 않는다.
- 오류·구버전·미설정·수집 누락·오래된 데이터가 정상이나 0건으로 표시되지 않는다.
- 계측 실패 격리와 기존 변환 계약 검증 근거, 배포·호환성·롤백 런북이 있다.
- 필수 CI 통과와 최신 head의 actionable review 해소. 병합 전에는 DONE으로 기록하지 않는다.

## Non-goals

장기 통계·p50/p95·자동 경보·외부 synthetic·전체 결과 품질·영속 큐·운영 조작·운영 배포.
#121은 열린 상태로 남기며 내부 페이지는 외부 장애 감지를 대체하지 않는다.
