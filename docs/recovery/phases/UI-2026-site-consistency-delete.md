# UI-2026 — 화면 일관성과 내 악보 삭제 흐름

Status: `DONE`
Base: 2026-09-22 `main`; #146의 DS-1 토큰과 기존 기능 계약 유지.

## Objective

홈·탐색·업로드·내 악보·로그인과 공통 상태/폼/모달을 실제 화면에서 점검하고, 기존
토큰을 기준으로 명백하게 어긋난 표현을 정리한다. 내 악보 삭제는 대상을 충분히
식별하고 영구 삭제를 명시적으로 확인하며, 진행/실패를 같은 맥락에서 보여준다.

## Work stages

1. 운영 화면을 읽기 전용으로 데스크톱·모바일에서 확인하고, 기존 토큰·컴포넌트와
   색상·타이포·간격·버튼·카드·입력·모달·상태 기준을 문서화한다.
2. 변경 전 회귀 테스트로 취소, 명시적 확인, 중복 제목 구분, 진행 중 중복 실행,
   실패 시 재시도 가능 상태, 키보드 포커스를 고정한다.
3. 공통 확인창과 내 악보 카드/목록 및 같은 카드가 쓰이는 분류 목록을 개선한다.
   API, 저장 데이터, 삭제 순서, 검색·정렬·업로드·재생 계약은 유지한다.
4. 관련 단위/E2E, 타입, 린트, 빌드, 실제 브라우저 데스크톱·모바일 화면을 검증한다.

## Shared UI standard

| 영역 | 기준 |
|---|---|
| 색상 | `globals.css`의 `--ck-*` 라이트 토큰만 사용한다. 본문 잉크, 보조 잉크, 테라코타 강조, 오류/진행/완료의 상태 색을 의미대로 쓴다. 상태는 문구·아이콘도 함께 둔다. |
| 타이포그래피 | Geist 본문, `text-ink` 제목, `text-ink-muted` 설명. 페이지 제목은 공통 `PageHeader`, 카드 제목은 `text-lg font-semibold`를 사용한다. |
| 간격·표면 | 페이지 여백은 `Container`와 `--ck-space-*`, 카드·모달은 흰 표면과 `border-rule`, 보조 블록은 `surface-muted`. 묶음 내부는 8/12/16/24px 간격 계열을 쓴다. |
| 버튼 | 공통 `Button`의 primary/outline/ghost/danger를 역할에 맞게 쓴다. 터치 동작은 최소 44px, 비활성·진행 상태를 구별하고 전역 `:focus-visible` 링을 유지한다. |
| 카드 | 공통 `Card`의 둥근 테두리·표면을 쓰고, 주 동작과 관리 동작의 위계를 분리한다. 제목은 줄바꿈하며 상태 변화에 따라 주 동작 높이를 바꾸지 않는다. |
| 입력 폼 | 보이는 레이블, `border-rule-strong` 경계, 가까운 오류 문구, 포커스 링을 사용한다. 필수/선택 상태와 단위를 명시한다. |
| 모달 | 제목·설명 연결, 취소 기본 포커스, 내부 Tab 순환, 닫힌 뒤 호출 버튼 포커스 복귀. 모바일에서 가로 넘침 없이 내부 스크롤하며 동일한 Button·표면 토큰을 쓴다. |
| 상태 | 로딩에는 접근 가능한 이름, 오류에는 원인과 다음 행동, 빈 상태에는 맥락에 맞는 행동을 제공한다. 처리 중 요청의 중복 실행을 막는다. |

시각 에셋은 추가하지 않는다. 악보/업로드/오류는 기존 실물 이미지와 선형 아이콘으로
충분히 설명되며 장식 이미지가 삭제 흐름의 이해를 돕지 않는다.

## Completion criteria

- 삭제 대상의 제목과 보조 식별 정보가 확인창에 표시된다. 영구 삭제와 연결된
  연습 데이터 손실을 명시하고, 확실하지 않은 파일 완전 제거를 단정하지 않는다.
- 취소를 기본 포커스로 둔다. 확인은 별도 선택 뒤에만 가능하며, 진행 중 닫기·
  중복 요청을 막고 실패는 창 안에서 알린다. 성공 후에만 창이 닫힌다.
- 공통 토큰, 44px 터치 영역, 좁은 화면의 줄바꿈·스크롤, 포커스 이동과 복귀,
  로딩·오류 상태가 확인된다.
- 기존 삭제 API와 데이터 처리 코드에 변경이 없고, 관련 검증·시각 근거가 저장소에
  기록되며, review-ready PR의 CI와 actionable review가 처리된다.
- PR 병합은 사용자 명시적 승인이 있기 전까지 하지 않는다.

## Constraints

운영의 실제 데이터 삭제는 검증에 사용하지 않는다. 운영 읽기 전용으로 확인창까지만
살피고, 완료/실패 경로는 로컬 모의 요청과 테스트로 검증한다.
