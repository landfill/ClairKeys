## Review findings fixed — 2026-09-12

Head moved to `1304be5`. Codex raised two P2 findings and both were correct; each had cancelled
part of this slice's own purpose, so both were fixed rather than deferred.

1. **Focus ring suppressed.** The card links carried `focus-visible:outline-none`, so a keyboard
   user got a shadow change instead of the repository's 2px ring. `src/app/globals.css` does not
   just define that ring — its comment states that `outline: none` must not appear anywhere and
   records that `.playback-controls .slider:focus` had already cost the slider its indicator the
   same way. Making cards keyboard-reachable and then hiding where focus landed is worse than
   leaving them unreachable, because it looks finished. The override is removed from all three
   card links.

2. **Modified clicks swallowed.** `onClick` called `preventDefault()` unconditionally, and
   `/explore` always supplies `onSheetMusicClick`, so Cmd/Ctrl-click and Shift-click router-pushed
   in the current tab. Open-in-new-tab was a stated reason for using real links and did not work
   on the only page that renders this component. `linkProps` now returns early for `metaKey`,
   `ctrlKey`, `shiftKey`, `altKey` or `event.button !== 0`; a plain primary activation still uses
   the caller's existing navigation.

Both are measured rather than trusted. jsdom computes no outline, so the E2E focuses the first
card and asserts computed `outlineStyle` is not `none` and `outlineWidth` is at least 2px; the
unit suite asserts no element carries an `outline-none` class, since that is the form the
regression took. For clicks, the unit suite checks all four modifiers plus middle-click leave the
handler uncalled and `defaultPrevented` false while a plain click calls it once, and the E2E
asserts a `ControlOrMeta` click leaves the URL unchanged before a plain click navigates.

Verification after the fix: `npx jest src/components/browse` 10/10; `e2e/explore-cards-responsive.spec.ts`
45/45 across five browser projects; full jest 1006 passed with the same single pre-existing
`fastapi` failure; tsc, ESLint and build clean.

The full Playwright run showed one failure in `e2e/playback-session-transition.spec.ts` on webkit
phone portrait. That spec depends on audio startup timing, this branch touches no playback file,
and a repeated re-run of that spec passed 12/12, so it is recorded as a flake rather than a
result. Both review threads were answered on the PR.
