## Why this shape

Same rationale as the volume control: the right brightness is a listening judgement, so a live slider
whose readout is the tuning constant lets the value be chosen by ear and read off as the new
`DEFAULT_TREBLE_ROLLOFF`. Parameterising `harmonicAmplitudes` with a default keeps the pure function
and every existing caller/test unchanged.

## The one real difference from volume, made explicit

Volume is a single downstream `GainNode`, so a change is heard on everything immediately. Treble
rolloff is consumed when a note's `PeriodicWave` is built, so it **cannot retune notes already
scheduled** — a change is audible only from the next note the scheduler creates. During playback the
notes already in the look-ahead window finish on the old brightness. This is documented in the control
comment and the label, so it is not mistaken for a lag bug.
