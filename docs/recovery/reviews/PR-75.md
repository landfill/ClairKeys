## 핵심 설계

회전 조건을 `engaged && (pointer: coarse) && (orientation: portrait)` **한 줄**로 둔다.
Android의 `lock()` 성공은 화면을 실제 가로로 만들어 portrait 질의를 스스로 종료시키므로,
**이슈가 요구한 "이중 회전 해제"가 별도 분기 없이 같은 식에서 나온다.** 사용자가 직접 기기를
돌린 경우도 동일하게 처리된다.

iOS 판별은 `typeof screen.orientation?.lock === 'function'`으로만 한다 — iOS는 인터페이스
자체는 Safari 16.4+로 제공한다. 방향 요청은 재생 클릭 핸들러에서 **동기적으로** 발사한다
(`play()`가 await하는 동안 fullscreen의 transient activation 창을 잃기 때문).

## 리뷰 지적 R1·R2·R3 — 3건 모두 실제 결함, 전부 수정

코드에 대조해 검증한 결과 3건 모두 유효했다. 회귀를 먼저 단독 커밋(`ccacbb1`)한 뒤 수정했다.

### R1 — 재생 시작 전 `orientation.exit()` (Major)

**이 결함은 iOS에서 기능을 완전히 죽인다.** `usePlaybackOrientation`이 매 렌더 새 객체를
반환하므로 그것을 deps에 넣은 effect가 매 렌더 재실행되고, `enter()`의 `setEngaged(true)`가
유발한 렌더에서 `isPlaying`은 아직 `false`다(`play()`가 AudioContext·샘플을 await 중).
effect가 그 false를 읽고 `exit()`를 호출해 방금 건 요청을 취소한다. CSS 회전이 유일한 수단인
iOS에서는 **회전이 아예 나타나지 않는다.**

기존 컴포넌트 테스트는 hook을 **안정 객체로 mock**해서 이 재실행 고리를 재현하지 못했다 —
실제 hook이 갖지 못한 성질을 mock이 갖고 있었다. 이것이 이 지적이 CI를 통과한 코드에서 나온 이유다.

수정: hook이 `useMemo`로 안정 객체를 반환하고, effect는 `true → false` 전이에서만 `exit()`한다.
`useFallingNotesPlayer.play()`가 시작 성공 여부를 반환하도록 해 시작 실패 시에도 되돌린다 —
`isPlaying`만으로는 "아직"과 "영영"을 구분할 수 없다.

### R3 — 세션 종료 후 도착하는 요청 (Major)

`requestFullscreen()` 응답 전에 정지·이탈하면 나중에 resolve된 체인이 `lock('landscape')`를 걸고
`lockedRef`를 세운다. **해제할 주체가 사라진 뒤에 잠그는** 것이라 화면이 가로로 고정된 채 남는다.

수정: 요청마다 generation을 부여하고 `exit()`·unmount가 무효화한다. 종료 후 도착한 체인은 락을
걸지 않고 이미 받았을지 모르는 fullscreen을 `release()`로 되돌린다.

### R2 — 탐색 막대 키보드 접근 (Minor) — 결함 인정, 제안은 미채택

제안된 `input[type=range]`는 채택하지 않았다. React는 range의 `onChange`를 `input` 이벤트에
매핑하므로 드래그 한 번에 수십 번 발화하는데, 이 화면의 `onSeek`는 매번 `startAudio`로 오디오
스케줄을 재구성한다 — 드래그가 재시작 폭풍이 된다. 대신 `role="slider"` + `tabIndex` +
`aria-valuemin/max/now/text` + 방향키·Home·End로 만들었다. 키 입력은 이산적이라 한 번에 한 번만
seek한다(기본 5초, Shift 1초).
