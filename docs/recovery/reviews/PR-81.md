두 번 다 상한 **값**을 바꿨을 뿐 "폰에서는 어떤 상한도 걸리지 않는다"는 **구조**를 고치지
못했다. `100dvh`가 동적 뷰포트라 주소창이 접히면 50~60px이 돌아오고, 건반이 더 못 자라므로
그 픽셀이 전부 낙하 영역으로 갔다 — 사용자가 본 "계속 커진다"가 이것이다.

## 접근

낙하 영역의 상한을 **건반 높이 × 1.15**로 둔다. 건반이 피아노 비율(6.3) 목표에 닿는 순간 낙하
영역도 멈추고, 남는 높이는 여백이 된다. `MAX_LOOK_AHEAD_SEC`(2.5s)는 초고해상도 안전망으로
남긴다(흰건반 49px → 건반 309px → 비례 상한 355px에서 다시 걸린다).

**화면 크기 임계값은 두지 않았다.** "가용 470px 미만이면 상한 1.2s"가 데스크톱을 지킬 수
있었지만 경계값의 근거가 없고 태블릿이 그 위에 걸친다. 사용자가 트레이드오프를 명시적으로
선택했다 — 규칙 하나 대신 데스크톱 2.50s → 1.39s.
