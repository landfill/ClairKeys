## 리뷰어가 볼 만한 지점

1. **범위가 이슈 본문보다 넓다 — 삭제가 포함된다.** 이슈는 "정렬"을 요구하지만 컨트롤 7개 중 동작하는
   것이 0개였다. 시각만 고치면 가짜가 더 진짜처럼 보이므로 허구를 먼저 걷어냈다. 특히 **계정 삭제**는
   눌러도 아무 일이 없어 "삭제했다"고 믿게 만들고, **가입일 `"2024년 1월 1일"`** 은 거짓이었으며,
   **비밀번호 변경**은 OAuth 전용 앱에 존재할 수 없는 항목이다.
2. **`ProfileSettings.tsx`를 재스타일링이 아니라 삭제했다.** 목업을 걷어내면 남는 내용이 없었고 다른
   import가 0개다. 되살릴 필요가 생기면 #112의 선행 조건부터다.
3. **새 라우트의 권한 경계.** `GET /api/user/profile`은 id 파라미터가 없어 호출자가 자기 행만 읽는다.
   회귀가 이를 고정한다(익명 401, 세션 id로만 `findUnique`, 404, 500에 DB 오류 미노출).
4. **셸 검사가 vacuous해지지 않게 고쳤다.** h1 개수 검사는 옛 페이지도 통과시켰다(h1을 이미 가짐).
   `MainLayout`이 만드는 `<main>` 랜드마크를 보도록 바꿔야 의도대로 실패했다.
5. **아바타 테스트가 실제 결함을 찾았다.** `OptimizedImage`가 기본 lazy라 페이지 최상단 요소가 스크롤을
   기다리고 있었다. 첫 구현은 Jest 전체가 통과하는데 `tsc`만 실패했다 — 그 경로를 어떤 테스트도 타지
   않았다는 뜻이었다.
