## 결함 요약

`FallingNotesPlayer`의 시각화 박스 안에는 `height: '100%'`인 flex 컬럼 래퍼가 있다. 이 래퍼는
PR #67 **이전에도 있었고**, 그때는 부모가 `style={{ height: 330 }}`로 픽셀 높이를 명시했기
때문에 100%가 328px로 풀렸다. PR #67이 재생 중 부모를 `{ flex: 1, minHeight: 0 }`로 바꾸면서
부모에 **선언된** 높이가 사라졌고, Chrome은 `height: 100%`를 `auto`로 처리한다. 래퍼는
in-flow 자식 중 유일하게 높이를 가진 건반(120px)까지 줄고, `flex: 1`인 낙하 영역은 0px로
붕괴한다. `FallingNotes`는 여전히 JS가 계산한 `fallingHeight`를 좌표계로 쓰므로 노트가
붕괴 지점(= 건반 위치)에서 시작해 그 아래로 그려진다.

**두 번째 결함(PR #67 이전부터 존재)**: 낙하 영역에 `overflow: hidden`이 없어 히트라인을
지나 지속되는 노트가 계속 그려졌다. 낙하 영역은 `position: relative`이지만 `z-index`가 없어
stacking context를 만들지 않으므로, 노트(`z-index: 20`)가 흰건반(`z-index: 10`) 위에 얹혔다.
