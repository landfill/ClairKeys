## 결함

`pr-checks.yml`의 path filter가 `src/utils/**`를 **어느 필터에도 넣지 않았다.** `frontend`는
`src/components|app|hooks|public`, `backend`는 `src/lib|services|prisma|app/api`만 본다.
`src/utils/`에는 `pianoLayout.ts`(모든 건반 위치와 노트 x), `visualUtils.ts`,
`dataConverter.ts`, `animationContract.ts`가 있고 전부 빌드 산출물과 렌더된 DOM에 도달한다.

**PR #77이 이 구멍을 드러냈다** — `src/utils/pianoLayout.ts`만 바꿨더니 Build Check,
Security Scan, Accessibility Check가 `skipping`이었다.

**구멍은 세 잡보다 넓다.** #77에서 Unit Tests와 E2E가 돈 것은 테스트 파일을 함께 바꿔 `tests`
필터가 걸렸기 때문이다. `src/utils/`만 바꾸고 테스트를 건드리지 않은 PR은 `Lint and Type Check`
하나만 돌고 나머지가 전부 skip된다. `src/types/**`, middleware, 빌드 설정도 같은 구멍이다.

## 접근

`core` 필터 신설(`src/utils`, `src/types`, middleware, `package.json`, `package-lock.json`,
`next.config.js`, `tsconfig.json`, `.github/workflows`)하고, `frontend`/`backend`로 게이팅하던
잡 5곳이 `core`도 받게 했다. 접근성 검사에 특히 필요하다 — `src/utils/` 변경은 렌더된 DOM에
도달하고(#77은 그려지는 건반 수와 옥타브 라벨 수를 바꾼다), 이 저장소에서 axe가 건반 관련
결함을 실제로 잡은 전력이 있다(PR #67).

## 검증 — 이 PR이 스스로의 증거다

`.github/workflows/**`를 `core`에 넣었으므로 이 변경 자체가 전체 잡을 트리거한다. 수정 전
필터에서는 `.github/workflows/`도 어느 필터에 없어 이 PR 역시 대부분 skip됐을 것이다.

**CI 결과: 18/18 pass.** Build Check, Security Scan, **Accessibility Check** 모두 실행됐다 —
