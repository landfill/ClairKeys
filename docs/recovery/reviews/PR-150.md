## Review findings addressed — 2026-09-08

- Two Codex reviews: the GitHub `chatgpt-codex-connector` bot posted one inline P2, and a locally
  dispatched Codex worker returned **request changes** with two P2s. They agreed on the E2E finding.
- **P2 · resume/loading deadlock (local Codex, reproduced and fixed in `44d3d45`).** Keeping the
  compact bar alive through a pause exposed a pre-existing hole in `useFallingNotesAudio.startAudio`:
  it sets `sampleStatus = 'loading'`, awaits the sample bank, and returns early on a superseded
  generation without restoring the status. Pause → seek or speed change calls `stopAudio()` with no
  replacement start, so `isReady` stayed false forever and **resume and stop were both disabled** —
  no way out of the player but the browser. Fixed with an in-flight load count: an abandoned start
  reports the bank when it is the last one out, and stays quiet while a newer start owns the status.
  The compact speed control also gained the `disabled={!isReady}` the setup screen always had.
  Two regression assertions fail on parent `37e766c` and pass after.
- **P2 · E2E skip too broad (both reviewers, fixed in `e0674fc`).** The skip asked only "did playback
  start?", so a real loss of the transition would have skipped in Chromium and WebKit and reported
  green. It now requires `browserName === 'firefox'`; every other project fails with a message saying
  so. The setup-screen guard assertions stay.
- Not adopted, recorded instead: paused seeking at 390px (the pre-existing compact-bar overflow, #146
  P2 responsive bundle) and the paused keyboard seek-step difference between the compact bar
  (5s arrows, no PageUp/Down) and the setup controls (1s arrows, 5s PageUp/Down). Neither is a
  behaviour this PR changed; both belong to the compact bar as D-019 shipped it.
- Replied on the inline thread. Final head `e0674fc`: **all 16 checks pass**, jest 995, E2E
  `47 passed, 3 skipped` (firefox only), and 50/50 locally with firefox not skipped.
