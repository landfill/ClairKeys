### 코디네이터 오류 1건 — 모델 id

첫 워커에 `--model terra`를 넘겼고 Codex가 400으로 거절했다:

```
{"type":"error","status":400,"error":{"type":"invalid_request_error",
 "message":"The 'terra' model is not supported when using Codex with a ChatGPT account."}}
```

실제 id는 `gpt-5.6-terra`다(사용자 `~/.codex/config.toml` 기준). 그 워커는 **18분간 프롬프트만 받은 채 아무것도 하지 않았다.**

**교훈 — `check --wait` 타임아웃만으로는 이 실패를 못 잡는다.** 가이드는 타임아웃을 "실패가 아니라 체크포인트"로 보라고 하고, 그 지침만 따르면 계속 기다리게 된다. 실패를 드러낸 것은 `worker-read`의 **transcript에 preamble 1건뿐이었다는 사실**이었다. `liveness: live`는 살아 있다는 뜻이지 일하고 있다는 뜻이 아니다. transcript가 비어 있으면 원본 터미널(`terminal read`)을 봐야 한다.

### 불변식 경계 조건 — 확인했고 문제 아님

`snapRangeToWhiteKeys`가 `Math.max(A0_MIDI, ...)` / `Math.min(C8_MIDI, ...)`로 클램프하므로, midi 20이나 109인 노트는 layout에 없고 `notesToVisualNotes`가 `if (!keyPos) continue`로 조용히 버린다. **프로브로 실제 재현했다.**

그러나 `normalizeAnimationData`가 `MIDI_MIN=21`/`MIDI_MAX=108` 밖 노트에 **throw**하고 재생 페이지는 모든 JSON을 이를 통과시킨다. **실제 재생 경로에서 도달 불가능**하며, 기존 88건반 고정 코드도 같은 성질이었으므로 회귀가 아니다.
