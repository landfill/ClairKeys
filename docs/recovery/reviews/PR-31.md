## Why this exists

`Security Audit` (`npm audit --audit-level high`, a required check) went red on `main` for the **third
time** in this pattern — a newly published advisory flips the gate with no dependency in the tree
having changed. `GHSA-mh99-v99m-4gvg` is a DoS in `brace-expansion` via unbounded expansion,
vulnerable range `<=5.0.7`. **31 of the 31 reported high entries trace to this one package**: jest and
eslint each pull it transitively, so one advisory inflates into a long chain.

It surfaced as the blocker on PR #30's `Security Audit` job (`908a3c6`), whose only red check was this
and which is otherwise green. Discovered while waiting on PR #30's CI under the user's "merge when CI
passes" instruction — the CI did not pass, and this is why.

This is the fourth occurrence of the time-dependent-gate failure mode (PR #25 sharp, PR #27
next-auth/next/postcss, and the `f39fbb6` observation). It is a property of the gate, not of any one
dependency, and it will recur.

## Fix shape

`brace-expansion` sits at both `1.1.16` and `2.1.2` in the tree, and the advisory's only fixed version
is `5.0.8` — there is no within-major patch. An `overrides` pin forces both chains to 5.0.8.

The package is a single stable function used only by dev tooling (`minimatch`/`glob` under jest and
eslint), so nothing in the runtime bundle is affected. The genuine risk is forcing one major's
consumers onto another major, which is why the acceptance check is the whole toolchain running green,
not just the audit number.
