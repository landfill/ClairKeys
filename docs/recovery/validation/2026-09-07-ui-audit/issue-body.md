## 목적

현재 제공하는 기능을 그대로 유지하면서, **악보를 고르고 연습을 시작하는 과정의 가독성과 화면 일관성**을 개선한다. 신규 기능 개발 없이 서비스 UI를 리뉴얼하는 제안이다. 이 이슈 등록은 구현·배포 승인을 뜻하지 않는다.

## 화면별 진단 및 리뉴얼 안

| 순서 / 화면 | 실제 관측과 상태 | 제안 |
|---|---|---|
| 1. 홈 `/` | **개선 필요.** 우측의 큰 검은 영역이 비어 있어 결과를 이해하기 어렵다. `HomeSamplePlayer` 소스도 정적 예시 대기 영역임을 명시한다. | 실제 기존 플레이어 화면을 바탕으로 한 정적 결과 이미지를 넣고 “연습 화면 예시”로 표시한다. 자동재생·새 체험 기능은 만들지 않는다. 설명·시작 버튼과 결과 이미지가 첫 화면에서 함께 읽히도록 높이를 맞춘다. |
| 2. 탐색 `/explore` | **개선 필요.** 추천 카드의 큰 면적을 동일한 “SHEET MUSIC / 악보 미리보기” 대체 영역이 차지한다. 추천·인기·최신에 같은 곡이 반복되고 표현 형식이 다르다. | 기존 세 섹션과 데이터 순서를 유지하되 제목·저작자·분류·동작의 순서를 통일한다. 실제 미리보기가 없는 카드는 제목 중심의 작은 표지로 바꾼다. 검색 탭·섹션 사이 여백을 줄여 악보가 더 빨리 보이게 한다. |
| 3. 내 악보 `/library` | **우선 개선.** 데스크톱 카드가 좁아 긴 제목·저작자가 잘리고 “수정/이동/삭제”가 글자 단위로 줄바꿈된다. 적은 카드가 왼쪽에 몰려 화면 활용도도 낮다. | 카드 최소 폭을 콘텐츠 기준으로 잡고 열 수를 줄인다. 제목 2줄, 저작자 1~2줄, 상태, 날짜, 연습 시작, 보조 동작 순서로 정렬한다. 버튼에는 충분한 폭을 주고 한글 단어 중간 줄바꿈을 막는다. 수정·이동·삭제와 기존 확인 대화상자는 그대로 보존한다. |
| 4. 업로드 `/upload` | **기본 구조 양호, 밀도 개선.** 파일 선택 영역과 세로 간격이 커서 첫 화면에는 곡명·저작자 정도만 보인다. 필수 항목과 선택 항목이 긴 한 흐름으로 이어진다. | 기존 단일 폼 안에서 “PDF 파일 / 필수 곡 정보 / 선택 설정”을 시각적으로 구획한다. 데스크톱 곡명·저작자를 2열로, 모바일은 1열로 배치한다. 파일 드롭 영역을 압축하고 파일 제한과 처리 안내를 유지한다. 필드·검증·기본값·제출 동작은 동일하게 둔다. |
| 5. 연습 준비 `/sheet/[id]` | **우선 개선.** 경고·사용 설명·컨트롤·전체 설정·음량이 위에 쌓여 실제 건반이 첫 화면 밖으로 밀린다. | 리듬 경고의 핵심과 확인 위치를 유지하며 안내를 짧은 묶음으로 정리한다. 재생/정지, A-B, 속도/음량을 하나의 일관된 툴바로 정렬한다. 기존 전체 설정 접힘을 활용하고 중복 설명의 세로 점유를 줄인다. |
| 6. 재생 ↔ 일시정지 | **재생 집중도는 양호, 전환 개선.** 재생하면 헤더 없는 집중 화면으로 바뀌고 일시정지하면 다시 설명이 긴 상세 화면으로 돌아간다. 같은 컨트롤의 위치와 모양도 크게 바뀐다. | 재생·일시정지에서 플레이어 프레임과 핵심 컨트롤 위치를 안정적으로 유지하는 표현을 목표로 한다. 현재의 재생 상태, 정지, 진행 위치, 반복·속도·음량 동작은 보존한다. 기존 집중 모드와 기하 관련 결정 개정이 필요하면 근거 문서를 먼저 고친다. |
| 7. 모바일 내 악보 | **기본 1열 재배치는 양호, 밀도 개선.** 첫 카드 전까지 큰 여백이 있고 카드 한 개가 화면의 상당 부분을 차지한다. 정렬 컨트롤 우측의 화살표가 본체와 떨어져 보인다. | 탭·검색·정렬의 세로 간격을 축소하고 카드 내부 여백을 줄인다. select 화살표 위치를 컨트롤 안에 맞춘다. 업로드 플로팅 버튼이 카드 동작을 가리지 않도록 하단 여백을 확보한다. |

## 공통 시각 규칙

- **기존 정체성 유지:** `--ck-canvas`, `--ck-surface`, `--ck-ink`, `--ck-accent`를 사용한다. 새 브랜드·다크 모드·새 테마를 추가하지 않는다.
- **정보 위계:** 화면 제목 → 현재 작업 → 주 행동 → 보조 정보 순서. 넓은 화면에서도 읽는 영역의 최대 폭을 제한하고 좌측 정렬선을 맞춘다.
- **컴포넌트 통일:** 버튼 높이·패딩, 카드 테두리·그림자, 탭, 배지, 입력창과 슬라이더를 기존 공용 컴포넌트 기준으로 맞춘다. 플랫폼마다 모양이 달라지는 장식 이모지는 기존 아이콘 체계로 정리한다.
- **타이포그래피 초안:** 제목 24~32px, 카드 제목 18px, 본문 16px, 보조 설명 14px를 출발점으로 한다. 실제 긴 한글·영문 제목에서 확인하며, 작은 글자로 억지로 공간을 맞추지 않는다.
- **상태 표현:** 현재 제공하는 로딩·빈 목록·검색 결과 없음·변환 중·실패·연습 가능 상태의 색·아이콘·문구·여백을 통일한다. 서버 상태나 오류 분류 자체는 늘리지 않는다. 원시 서버 로그를 노출하지 않는다.
- **접근성 검증 목표:** 키보드 초점 표시와 논리적 이동 순서를 유지하고, 주요 터치 동작은 44×44px 수준을 목표로 한다. 일반 본문 대비 4.5:1, 컨트롤·초점의 식별성, 200% 확대와 줄바꿈을 실제 렌더링으로 검사한다. 현재 화면의 대비 실패나 WCAG 준수를 확정한 것은 아니다.

## 기능 확장 금지선

포함: 배치·간격·타이포그래피·색상 토큰 적용·기존 컨트롤의 표현·기존 데이터의 문구·정적 예시 이미지·반응형 및 접근성 개선.

제외: 새 라우트, API/DB/애니메이션 스키마 변경, PDF 저장 또는 썸네일 생성 파이프라인, 새로운 검색/추천 로직, 연습 통계·진도·목표·점수·MIDI, 오선 악보 패널, 새 알림, OMR/운지 정확도 개선. 재생 시계·음표 타이밍·낙하 속도·손 배정·오디오 기본값도 이 UI 작업에서 바꾸지 않는다.

## 권장 실행 순서

1. **P1 · 가독성:** 내 악보 카드 폭/버튼 줄바꿈, 모바일 정렬 표시, 홈 정적 결과 예시.

3. **P2 · 일관성:** 탐색 카드, 업로드 폼, 공통 버튼/배지/아이콘/여백.
4. **P2 · 상태와 반응형:** 기존 상태 fixture, 모바일·확대·키보드 확인, 화면 비교 기록.

각 묶음은 목적별 PR로 나누고 동작 변경이 있는 경우 회귀 fixture를 먼저 준비한다. 위 순서는 제안이며 기존 OMR 작업의 우선순위를 자동으로 변경하지 않는다.
