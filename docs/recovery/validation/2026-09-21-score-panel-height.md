# 악보87·88·89 패널 높이 실측

Date: 2026-09-21 KST
사용자 기준: 충분히 보이면 높이를 변경하지 않는다. 이번 작업은 실측이며 UI 구현 변경 없음.

## 방법

운영 https://clairkeys.vercel.app/sheet/87, /88, /89의 공개 페이지에서 악보 ON → 재생 → 일시정지.
Aside 실제 Chromium 화면 1440×900 CSS px/DPR2, 기본 배율에서 SVG의 연속 두 staffline 그룹(양손 보표)을 묶어 실제 DOM bounding box 합집합 높이를 측정했다. 음표·운지·표현/페달 기호를 포함한다.
각 곡의 렌더링된 모든 시스템(악보 줄)을 측정했으며, 실제 스크롤 위치도 함께 저장했다. 오선 다섯 줄만의 높이가 아니다.
별도 Playwright Chromium에서 1366×768/1440×900/1920×1080, DPR1로 재생 레이아웃을 측정했다. 두 브라우저는 스크롤바/폰트 렌더링 차이가 있어 값을 혼용하지 않는다.
원시 수치: [JSON](2026-09-21-score-panel-height-measurements.json).

## 실제 브라우저 1440×900

외곽 패널306px, 표시 clientHeight289px. 테두리2px와 가로 스크롤바15px가 차지한다. clientWidth1359px 대비 SVG scrollWidth1374px.

| 악보 | 양손 묶음 최대 높이 | 표시 공간보다 큰 줄 | 판정 |
|---|---:|---|---|
| 87 Love Affair | 359.5px | 6줄 중 5줄 | 부족; 22초에서 높은음자리 윗부분 잘림 스크린샷 확인 |
| 88 Deborah's Theme | 270.5px | 6줄 중 0줄 | 높이 자체는 충분; 28초 현재 줄 양손·운지 표시 확인 |
| 89 Clair de Lune | 313.6px | 3줄 중 1줄 | 부족; 25초 두 번째 줄 상단 운지/슬러 일부 잘림 확인 |

87의 현재 두 번째 줄은350.2px로289px보다61.2px 크다. 89의 두 번째 줄은24.6px 부족하다.

## 결론과 한계

세 악보 모두 충분하다는 조건은 성립하지 않는다. 따라서 일괄 높이 유지의 근거로 사용할 수 없다. 88의1440×900 등 충분한 조건은 유지하고, 부족한 경우만 실제 시스템 높이를 고려하는 방안을 후속 후보로 남긴다. 높이 변경은 구현하지 않았다.
가로 overflow로15px를 잃는 것과 마디 box 상단 기준 자동 스크롤이 운지·슬러를 자르는 문제도 구분해야 한다. 가로 스크롤바 제거만으로87의 부족분은 해소되지 않는다. 단순 CSS 높이 증가만으로 모든 잘림이 해결됐다고 판단하지 않는다.
비로그인 미리보기로 현재 재생 구간을 시각 확인했고 전체 곡의 모든 줄은 DOM 치수로 확인했다. 로그인 상태 전체 재생 자동 스크롤·Safari·브라우저 확대는 미검증.
스크린샷/재현 스크립트는 Git 제외 local-test-data/score-height-20260921/에 있다. 원본 PDF/XML/악보 이미지를 저장소에 커밋하지 않는다. 영구 근거는 위 JSON 수치와 본 기록이다.

## 동일 로직의 높이 차이 — 추가 실측

2026-09-21 사용자 질문에 따라 동일1440×900 headless Chromium에서 각 staffline 첫 마디의 수평 오선5개를 직접 측정했다.
세 곡 모든 줄에서 오선 간격10px, 높은음자리 오선 높이40px, 낮은음자리 오선 높이40px로 동일했다. Zoom을 곡별로 변경하는 코드도 없다.
첫 줄의 두 오선 사이(윗보표 마지막 선→아랫보표 첫 선) 간격은87=110px,88=50px,89=92px다.
전체 줄의 간격 범위는87=109–130px,88=40–98px,89=80–122px다. 즉 동일 축척에서 보표 사이 배치가 다르다.
전체 높이는 위쪽 기호 공간 + 40 + 보표 사이 간격 + 40 + 아래쪽 기호 공간이다. 87의 마지막 줄은 아래쪽 공간만110.5px이며, 기존 스크린샷에서 페달 등 보표 바깥 기호를 확인했다.
[추가 원시 측정](2026-09-21-score-staff-spacing.json).

코드 근거: ScorePanel은 동일 OSMD 옵션으로 전체 score를 렌더링하고 운지를 above에 배치한다. annotateScoreFingering은 앱 운지를 음표에 추가한다.
설치된 OSMD EngravingRules/MusicSheetCalculator에는 staff distance, skyline/bottomline, fingering, slur 충돌 배치 규칙이 있다. 음역·화음 운지·슬러/강약/페달 등 입력 내용에 따른 배치 차이와 화면 폭에 따른 줄바꿈이 높이를 달라지게 한다. 각 기호의 개별 기여도와 MusicXML 원본 배치 속성 영향까지 분리한 실험은 하지 않았다.
현재 패널은 동일 clamp 높이이고 렌더링된 시스템 전체 높이에 맞추는 과정이 없다. UI 수정 없이 원인 설명만 수행했다.
