# 2026-08-27 — 피아노 샘플 게인 실측 (이슈 #60 근거)

PR #59 배포 후 사용자가 "음색은 만족하나 기본 음량이 약하다"고 보고해, 원인을 찾기 위해
`public/samples/piano/*.mp3` 30개 전부의 peak과 RMS를 측정했다.

- 측정 명령: `ffmpeg -hide_banner -nostdin -i <file> -af volumedetect -f null -`
- 도구: `ffmpeg-static` (저장소 환경에는 ffmpeg이 설치돼 있지 않아 npm으로 임시 확보)
- 대상 커밋: `67efc6d` (PR #59 병합 시점의 샘플 세트, manifest `v1`)

이 기록을 남기는 이유: 이 저장소 환경에 ffmpeg이 없어 재측정 비용이 든다. 이슈 #60을
처리하는 세션이 같은 측정을 반복하지 않도록 수치를 고정해 둔다. **샘플 세트를 재빌드하면
이 값은 무효가 된다** — manifest 버전이 `v1`이 아니게 되면 다시 측정해야 한다.

## 여기서 도출되는 사실

1. **`SAMPLE_SET_PEAK = 0.4111`은 정확하다.** MIDI 21이 -7.7 dBFS로 세트 최대이고
   `10^(-7.7/20) = 0.4115`다. `SAMPLE_PEAK_GAIN = 0.3 / 0.4111 = 0.730`도 일치한다.
   즉 계산 오류가 아니라 **기준 선택의 문제**다.

2. **크레스트(peak − RMS) 평균 20.0 dB** (범위 14.6 ~ 27.6). 녹음 피아노는 해머 타격의
   짧은 피크 뒤 낮은 감쇠음이 이어지는 반면 대체된 합성음은 지속 파형이라 크레스트가 작다.
   피크를 맞추면 RMS는 그만큼 낮고, 체감 음량은 RMS를 따른다.

3. **정규화 기준이 세트 최대치(A0)** 이므로 나머지 29개는 전부 목표 아래다.
   MIDI 55~85 구간 평균이 목표 0.300보다 **0.117 부족**하고, C5는 0.095로 약 1/3이다.

4. **헤드룸이 실제로 남아 있다.** 기존 분석은 "보이스가 0.3에 도달"을 전제했는데 실측상
   그것을 만족하는 것은 A0뿐이다:

   | 동시 발음 | 정렬 최악 합 | clip(1.0)까지 여유 |
   |---|---|---|
   | 4음 | 0.265 | 11.5 dB |
   | 8음 | 0.529 | 5.5 dB |
   | 12음 | 0.794 | 2.0 dB |

   현재 `DEFAULT_MASTER_GAIN = 0.22`, `MAX_MASTER_GAIN = 0.35`이므로 슬라이더를 끝까지
   올려도 +4 dB뿐이다.

## 검증하지 못한 것

- 합성 폴백 경로의 실제 크레스트는 측정하지 않았다. "샘플보다 작다"는 것은 파형 성질에서
  나온 추론이며 실측이 아니다. 두 경로의 게인 분리를 검토한다면 이 값이 필요하다.
- 음역 간 20 dB 편차 중 어디까지가 피아노라는 악기의 성질이고 어디부터가 녹음·트림·모노
  폴드의 부산물인지 구분하지 않았다. 이슈 #60의 안 C(샘플별 정규화)는 이 구분에 달려 있다.
